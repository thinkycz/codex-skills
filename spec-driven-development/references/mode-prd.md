# Prd

Extract screens, states, flows, actors, data and business behavior from supplied design sources. Distinguish visible evidence from inference and ask only material unresolved questions. Build a PRD only when requested or needed to resolve a genuinely incomplete source; avoid manufacturing another document from a sufficient specification. Map requirements to source nodes/screens and acceptance checks. Source acquisition can be repository-free.

# Conditional helpers

Use a source adapter only when source acquisition remains incomplete. For a multi-screen build use design-to-traversable-app; for visual polish use frontend-design implement. For real backend integration use integrating-backend-api-into-frontend. For specific requirement conflicts use requirements-review; brainstorming is reserved for genuinely ambiguous product direction.

Protect meaningful behavior and verify acceptance without mandatory helper loading. Consult full-project-hardening migration when migration risk needs an audit, or session-handoff resume when existing evidence is contradictory. Reuse established evidence; no PRD, router or discovery pass is mandatory merely because implementation is starting.

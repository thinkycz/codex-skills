# Activity-informed skill review

Use when the user asks to derive skill changes from recent conversations or computer activity. Evidence intake does not authorize live operations observed in those sources.

1. Establish the requested chat count/time window and sources. Combine accessible Codex and ChatGPT listings, include relevant archives, deduplicate by identity, exclude the current audit and worker histories unless requested, and order by actual update time. A capped sidebar response is not an exhaustive account export; use available read-only metadata or disclose the coverage limit.
2. Read user requests, later corrections and relevant outcomes, paging where available. For oversized turns, reduce the page size; when accessible native tools still cannot read the turn, use authorized local transcript files, streaming/decompressing a copy or read-only input. Treat response-item user messages and event formats according to the observed schema; do not silently mistake an empty parser result for an empty chat. Skip injected context and unrelated tool payloads.
3. If Computer History is requested, use its current skill and status tool first. Compare timestamps, begin with broad summaries and inspect focused events/detail as needed. Report gaps and distinguish observed actions, typed-but-unsubmitted text, assistant claims and verified outcomes. Do not change observation settings or start recording merely to complete a retrospective review.
4. Upgrade relevant discoveries to their owning source where useful: current source files, maintained docs or an authorized app read. An open terminal or old event is not permission to access production, send a message or alter a schedule.
5. Map corrections and repeated friction to existing owners before adding packages. Prefer a focused reference over a duplicate owner. Create a new package only for a distinct reusable workflow with a clear trigger and acceptance boundary; do not create a skill for every curiosity topic or globalize a project-specific design preference.
6. Keep committed usage evidence to sanitized aggregate counts and routing signals. Never copy private prompts, screenshots, customer/staff records, credentials, URLs containing tokens or absolute personal paths into reusable fixtures. Skill mentions are not actual source-load telemetry; absent cost/latency measurements remain unknown.
7. Update metadata, owner/mode registrations, scenarios and versions together. Preserve old evaluation evidence; source changes make it stale. Report static checks, lead-reviewed scenarios and independent evaluations as different evidence levels. Commit/push only when requested.

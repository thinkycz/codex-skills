# Correlate service latency

Use for intermittent 502/504s or slow API/database calls. Establish the authenticated route, payload, entity state, environment, timestamp/timezone and request ID before comparing observations. An unauthenticated rejection does not reproduce the slow authenticated path.

1. Correlate reverse-proxy status and per-upstream timings with application request lifecycle logs and dependency-call spans. Preserve the difference between total request duration and individual retry/connect/header/response times; identify which measurement each number represents. An immediate 502 and a timeout can have different causes.
2. Measure authentication, database/HTTP calls, response construction and event-loop delay separately. Many sequential reads can accumulate latency without blocking the JavaScript thread. Count repeated/per-item reads and compare equivalent authenticated requests before optimizing.
3. For Supabase/PostgREST, compare the same filter and data with direct SQL EXPLAIN and REST timing. A fast indexed SQL lookup does not explain a slow HTTP call, but an off-incident fast sample does not rule out transient database waits. Avoid adding an index without a query-plan/scan reason.
4. Capture database activity, wait events and blockers during the slow interval when authorized access exists. Distinguish the PostgREST pool from total PostgreSQL connections; low global connection usage cannot rule out a smaller pool wait. Neither a dashboard average nor an old idle snapshot proves the incident cause.
5. Check actual status/error evidence before attributing a delay to plan quotas, rate limits, locks, disk or provider incidents. Successful HTTP responses alone do not prove or disprove every throttling mechanism. Confirm an incident affects the relevant service and time window.
6. If access is unavailable or prohibited, request narrowly scoped proxy/application/provider evidence from the owner. Do not enter a production terminal merely because its app is open or past history shows the user using it. Keep identifiers useful for correlation while redacting credentials and personal payloads.
7. Optimize measured duplicate/serial work within authorization and compare representative before/after requests. Avoid unbounded fan-out, speculative retries or timeout increases that hide the problem. Report proven facts, supported hypotheses and the next discriminating observation separately.

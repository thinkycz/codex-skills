# Conditional debugging helpers

Use test-driven-development when a meaningful failing automated check can protect the proven boundary. Use verification-before-completion for detailed claim-to-evidence guidance. Use frontend-design implement for confirmed visual corrections and Figma/Stitch only when source context is missing. Use integrating-backend-api-into-frontend for an actual integration change and requirements-review for conflicting expected behavior. Do not load a router or create a PRD as a mandatory debugging step.

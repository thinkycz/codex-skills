# Delivery menu procedure

1. Select the requested merchant, platform and branch; record the active context. Inspect existing item/category names and variants before editing. Use existing authorized sessions; do not store credentials in the skill.
2. For a size-description change, identify every targeted variant and add the approved volume/unit exactly once. Preserve other product facts and options. Do not assume an M/L convention applies to an unrelated catalog.
3. For a bundle, identify both component drinks, included sizes, base prices, mandatory choices and optional extras. Calculate the comparable component sum minus the user-approved discount in the catalog currency. If an exact price or discount is missing, resolve it before a write; do not assume an old campaign remains authorized.
4. Use the requested separate bundle category when specified. Preserve existing items and avoid duplicate categories. Configure component choices so buyers can obtain the advertised bundle for its displayed base price, with applicable sugar/ice/topping choices and clear surcharges.
5. Save one scoped change at a time. Reload/search after an uncertain save before retrying creation. Verify names, category, price, component sizes, option requirements and availability in the persisted merchant view and customer preview where supported.
6. Distinguish draft, saved, submitted for review, published and observed customer-visible states. Publish when the current request authorizes going live; otherwise leave the requested draft/submission state. Do not place an order to test a menu.

Report a compact platform/branch/change/price/publication/verification checklist. A missing platform login blocks only that platform; finish unaffected authorized catalogs and state the remaining blocker.

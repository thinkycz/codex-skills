# Exact-variant comparisons

Establish the decision and the facts that distinguish candidates. Reuse known constraints; ask only for a missing requirement that would materially change the answer. An ordinary follow-up can extend the research without requiring a new formal brief.

- Identify exact model/part/board number, regional variant, installed software, and intended use for hardware. Family names are insufficient for SIM support, keyboard mechanisms, firmware support, ports or GPU compatibility. Separate newest available software from newest software supported by that model.
- For travel, compare the same route, dates, travelers, fare conditions, baggage and total journey. Distinguish nonstop, same-flight-number stops, and connections; verify schedules and availability at research time. Do not preserve a past quote as a current offer.
- For cost comparisons, use the user's actual receipt/quote where available, preserve discounts and order channel, state assumptions, and show the small calculation needed for the decision. Do not silently combine different quantities, currencies or restaurant/store prices.
- Use current primary sources for technical specifications, support claims and changing official facts. Clearly distinguish an announcement, forecast, displayed search result and a currently bookable/deliverable option. Link to the page supporting each claim.
- When the user asks for real experiences, seek firsthand accounts and label them anecdotal. A few forum reports do not establish a population-wide conclusion or override an official technical constraint. If no credible evidence is found, leave that point unresolved.
- Present a concise comparison with the factors that matter and a recommendation when requested. Mark inference and conflicting evidence explicitly. Preserve the user's response language unless translation is requested separately.

Research does not book, buy, send, change device settings or implement code. Move to an execution workflow only within the user's actual authorized request.
